# invitations

A React + Vite project for a polished invitation landing page.

## Getting started

```bash
npm install
npm run dev
```

Then open http://localhost:5173 in your browser.

## Production build

```bash
npm run build
```

## «Ձեր սեղանը» (հյուրի սեղանը հրավերում)

Հյուրը հրավերում գրում է իր անունը և տեսնում իր սեղանը։ Սեղանի ցուցակը երևում է միայն զույգի ընտրած պահից (Երևանի ժամով), իսկ մինչ այդ բաժնում միայն ամսաթիվն է։ Հյուրը երբեք չի տեսնում ամբողջ ցուցակը. սերվերը պատասխանում է միայն մեկ սեղանով կամ «չգտանք»։ Այն հեռախոսում, որտեղ սեղանը գտնվել է, հաջորդ անգամ այն երևում է միանգամից։

Հիմա բաժինը կա միայն **wd-portrait** դիզայնում։ Մյուս հրավերներում ոչինչ չի փոխվել։

**Մեկ անգամ (production).** Supabase SQL editor-ում գործարկեք `supabase/seating.sql`-ը։ Ֆայլն ավելացնում է միայն նոր աղյուսակներ, ու այն կարելի է գործարկել կրկին։

**Ամեն զույգի համար.**

1. Զույգից վերցրեք ցուցակը CSV ֆայլով (Excel-ում՝ «Save as → CSV UTF-8»)։ Սյունակներն են `guest_name` և `table_label`, տես [scripts/seating.example.csv](scripts/seating.example.csv)։
   - Մեկ տող՝ մեկ հյուր կամ զույգ (օր.՝ «Արամ և Լիլիթ Սարգսյաններ»)։
   - Սեղանը կարող է լինել թիվ կամ բառ («7», «VIP», «Ընտանիք»)։
   - Անունները կարող են լինել հայերեն, լատինատառ կամ ռուսերեն։ Որոնումը դրանք համարում է նույնը (Անի = Ani = Ани)։
2. Ստուգեք ֆայլը՝ առանց որևէ բան փոխելու.
   ```bash
   node scripts/import-seating.js --invitation <կոդ> --file seating.csv --reveal-at "2027-09-18 18:00" --dry-run
   ```
   `<կոդ>`-ը հրավերի հղման 12 նիշն է `/i/`-ից հետո։
3. Ներմուծեք նույն հրամանով, առանց `--dry-run`-ի։ Script-ը ցույց կտա, թե քանի անուն է ավելացել, թարմացվել ու հեռացվել, և որ տողերն են բաց թողնվել ու ինչու։

**Փոփոխություններ.**

- Նոր ցուցակը ներմուծվում է նույն ձևով։ Ցուցակը դառնում է ճիշտ այն, ինչ ֆայլում է. նորերն ավելանում են, փոխվածները թարմացվում են, ֆայլում չեղածները հեռացվում են։
- Բացման ժամը փոխելու համար՝ `--reveal-at "..."` (առանց `--file`-ի)։
- Բաժինը թաքցնելու համար՝ `--off`, նորից ցույց տալու համար՝ `--on`։ Ցուցակը չի ջնջվում։

Script-ը օգտագործում է `.env.local`-ի `SUPABASE_URL` և `SUPABASE_SERVICE_ROLE_KEY`-ը։

**Լոկալ ստուգում.** `npm run demo:payments`-ը տպում է wd-portrait-ի օրինակ հղումներ յուրաքանչյուր վիճակի համար. առանց սեղանների, մինչև բացումը, բացված (hy/ru/en)։ Թեստերը՝ `npm run test:seating`։

## «Անհատական դիմում հյուրին» (անհատական հղումներ)

Երբ պատվերն ունի «Անհատական դիմում հյուրին» հավելումը, յուրաքանչյուր հյուր կարող է ստանալ իր հղումը՝ `siloona.am/i/<կոդ>/<token>`։ Այդ հղումով հրավերը դիմում է նրան անունով («Սիրելի Արամ և Անի»), իսկ RSVP ձևում անունն արդեն լրացված է։ Ընդհանուր հղումը մնում է նույնը, իսկ գոյություն չունեցող հղումը բացում է սովորական հրավերը։

**Մեկ անգամ (production).** Գործարկեք `supabase/addons.sql`-ը, ապա `supabase/personal-links.sql`-ը։

**Ամեն զույգի համար.**
1. Զույգից վերցրեք ցուցակը CSV ֆայլով. սյունակը `display_name` է (ըստ ցանկության՝ `phone`, `note`), տես [scripts/guests.example.csv](scripts/guests.example.csv)։
2. Ստուգեք ֆայլը.
   ```bash
   node scripts/import-guests.js --invitation <կոդ> --file guests.csv --dry-run
   ```
3. Ստեղծեք հղումները.
   ```bash
   node scripts/import-guests.js --invitation <կոդ> --file guests.csv --out links.csv
   ```
   `links.csv`-ում յուրաքանչյուր անունի կողքին նրա հղումն է. ուղարկեք այն զույգին։ Եթե հավելումը վաճառվել է ոչ checkout-ով, ավելացրեք `--enable`։

Կրկին գործարկելիս ավելանում են միայն նոր անունները, իսկ եղածները պահում են իրենց հղումը։ Հղումները պատահական են (24 նիշ) և չեն բացահայտում այլ հյուրերի անունները։
