# Siloona · Claude Code prompt-ներ checklist-ի բաց կետերի համար

Prompt-ները տուր VS Code-ում **մեկը մյուսից հետո**: յուրաքանչյուրից հետո ստուգիր արդյունքը, հետո անցիր հաջորդին։
Հերթականությունը ըստ կարևորության է. 1–3-ը պետք է ավարտել մինչև 7.12-ի փակ մեկնարկը։
`[ ]` նշված տեղերը լրացրու նախքան ուղարկելը։

## 1 · Կոնտակտներ, ՀՏՀ և «Մեր մասին» (checklist 26, 28, 31)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Նախ ուսումնասիրիր նախագծի կառուցվածքը և այն ֆայլերը, որոնք վերաբերում են կոնտակտներին, ՀՏՀ-ին և «Մեր մասին» բաժնին։ Մի փոխիր այլ էջեր, ոճեր կամ տառատեսակներ։

Առաջադրանքներ.

1. Կոնտակտներ (contacts.js, footer, «Գրել մեզ» կոճակ)։ Թեստային տվյալները փոխարինիր իրականներով.
   - Telegram: [@username]
   - Viber / WhatsApp հեռախոս: [+374 ...]
   - Email: [hello@siloona.am]
   - Instagram: @siloona.am
   Ստուգիր, որ բոլոր հղումները ճիշտ ձևաչափով են (t.me/..., viber://chat?number=..., wa.me/..., mailto:) և բացվում են հեռախոսում։ Գտիր կոդում բոլոր տեղերը, որտեղ մնացել է թեստային կոնտակտ, և ցույց տուր ցանկը։

2. «Մեր մասին» բաժնի ABOUT_PHOTO. նկարի alt տեքստը «Siloona-ի հիմնադիրը»-ից փոխիր չեզոքի (օր.՝ «Siloona-ի ատելիեի աշխատանքային սեղանը»)՝ 3 լեզվով։ Ինքը նկարը մի փոխիր։

3. ՀՏՀ (FAQ)։ Ավելացրու կամ թարմացրու հետևյալ հարցերը 3 լեզվով (hy/ru/en)՝ պահպանելով բաժնի առկա ոճն ու կառուցվածքը.
   - Ինչպես կապվել մեզ հետ (Telegram, Viber, WhatsApp)
   - Որքան ժամանակում եմ ստանում հրավերը. պատրաստի ձևանմուշ՝ վճարումից անմիջապես հետո, հարմարեցված՝ [ժամկետ], անհատական՝ [ժամկետ]
   - Վճարում. [ինչպես ենք վճարում ընդունում մինչև ArCa-ի միացումը]
   - Վերադարձ. [քաղաքականությունը մեկ նախադասությամբ]
   Եթե [ ]-ով նշված տեղը դատարկ է, այդ հարցը մի ավելացրու և ինձ ասա։ Մի հորինիր գներ, ժամկետներ կամ պայմաններ։

Ստուգիր desktop-ում և 375px լայնությամբ mobile-ում։ Վերջում գրիր, թե որ ֆայլերն ես փոխել և ինչ ես ստուգել։
```

## 2 · Հղման նախադիտում և պատվերի email (checklist 34, 35)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Նախ ուսումնասիրիր, թե ինչպես են կառուցված հրավերների հանրային URL-ները, պատվերի ձևակերպումը և Supabase-ի աղյուսակները։ Մինչև փոփոխություն անելը նկարագրիր պլանը կարճ, եթե այն պահանջում է ճարտարապետական փոփոխություն։

Առաջադրանքներ.

1. Անհատական նախադիտում (Open Graph) հրավերների հղումների համար։
   Երբ հրավերի հղումն ուղարկվում է WhatsApp, Telegram, Viber կամ Instagram, նախադիտումը պետք է ցույց տա.
   - վերնագիր՝ հրավերի անունները և ամսաթիվը (օր.՝ «Աննա & Միքայել · 12.06.2027»),
   - նկարագրություն՝ կարճ տող միջոցառման տեսակով,
   - նկար՝ տվյալ դիզայնի նախադիտման նկարը (1200×630)։
   Vercel-ում սա կարելի է անել serverless function-ով կամ middleware-ով, որը crawler-ների համար վերադարձնում է HTML՝ og:title, og:description, og:image տեգերով։ Օգտագործիր միայն անվճար լուծումներ, առանց նոր վճարովի ծառայությունների։ Եթե դիզայնի համար նախադիտման նկար չկա, օգտագործիր Siloona-ի ընդհանուր նկարը։
   Ստուգիր Facebook Sharing Debugger-ով կամ curl-ով՝ «facebookexternalhit» և «TelegramBot» user-agent-ներով։

2. Պատվերի հղումը email-ով։
   Վճարումից կամ պատվերը ձևակերպելուց հետո հաճախորդը պետք է email ստանա.
   - պատվերի համարը,
   - հրավերի հղումը,
   - «Իմ պատվերները» էջի հղումը,
   - կոնտակտները՝ հարցերի համար։
   Ընտրիր անվճար տարբերակ (օր.՝ Resend-ի կամ Brevo-ի անվճար պլանը) և նախ ինձ ասա, թե ինչ է պետք գրանցել և ինչ environment փոփոխականներ ավելացնել Vercel-ում։ Email-ի տեքստը գրիր 3 լեզվով՝ ըստ այն լեզվի, որով պատվերն արվել է։ Ոճը՝ պարզ, Siloona-ի գույներով (ivory #F7F3EC, burgundy #8F1028), առանց ավելորդ դիզայնի։ Email-ի ձախողումը չպետք է արգելափակի պատվերը. գրանցիր սխալը և շարունակիր։

Վերջում գրիր, թե որ ֆայլերն են փոխվել, ինչ է պետք ինձնից (բանալիներ, DNS գրառումներ) և ինչ ես ստուգել։
```

## 3 · Production-ի պատրաստություն (checklist 37, 38, 40, 45)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Այս առաջադրանքում կոդը մի փոխիր առանց անհրաժեշտության. նպատակը ստուգումն ու ձեռնարկն է։

1. Անցկացրու բոլոր ավտոմատ թեստերը (tests/payments և մնացածը)։ Եթե թեստ է ձախողվում, բացատրիր պատճառը և առաջարկիր ուղղում. ուղղիր միայն այն, ինչը ակնհայտ սխալ է։

2. Ստուգիր schema.sql, payments.sql, guest-links.sql ֆայլերը.
   - կարելի՞ է դրանք գործարկել դատարկ production Supabase-ում այս հերթականությամբ,
   - կա՞ն արդյոք RLS քաղաքականություններ բոլոր աղյուսակների համար,
   - հյուրերի RSVP պատասխանները չե՞ն կարող կարդալ ուրիշները։

3. Կազմիր DEPLOY.md ֆայլ՝ քայլ առ քայլ ձեռնարկ ինձ համար.
   - SQL ֆայլերի գործարկման հերթականությունը,
   - Vercel-ի բոլոր environment փոփոխականների ցանկը (անունը, որտեղից վերցնել, պարտադի՞ր է)՝ PUBLIC_SITE_URL=https://siloona.am, Supabase, Telegram bot, Idram, ArCa, email,
   - ստուգիր, որ RATE_LIMITS-ը production-ում միացված է,
   - ինչպես ստուգել, որ ամեն ինչ աշխատում է deploy-ից հետո։

4. Supabase-ի անվճար նախագիծը անգործության դեպքում կարող է դադարեցվել, և այդ դեպքում հյուրերի հրավերները չեն բացվի։ Ստուգիր, արդյոք հրավերների բացումը կախված է Supabase-ից, և առաջարկիր անվճար լուծում (օր.՝ Vercel Cron, որը օրը մեկ անգամ հարցում է անում)։ Մի իրականացրու առանց իմ հաստատման։

Վերջում գրիր արդյունքը կարճ. ինչն է պատրաստ, ինչն է պետք ինձնից։
```

## 4 · Արագություն, SEO և 404 (checklist 36, 42, 43, 44)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Մի փոխիր դիզայնը, տեքստերը կամ տառատեսակները։

1. Վերլուծություն։ Միացրու Vercel Web Analytics-ը (անվճար)։ Ավելացրու custom event-ներ. դեմոյի բացում, «Պատվիրել» կոճակի սեղմում, պատվերի ավարտ։ Մի ավելացրու cookie banner պահանջող գործիքներ։

2. Նկարներ։ Գտիր 200 ԿԲ-ից մեծ բոլոր նկարները (օր.՝ closing-embrace.png՝ 930 ԿԲ)։ Փոխարկիր WebP-ի կամ սեղմիր՝ առանց տեսանելի որակի կորստի, ավելացրու loading="lazy" այն նկարներին, որոնք առաջին էկրանում չեն։ Ցույց տուր աղյուսակ՝ ֆայլ, չափը առաջ, չափը հետո։

3. SEO։ Ավելացրու sitemap.xml (գլխավոր, կատալոգ, դիզայնների էջեր, իրավական էջեր՝ 3 լեզվով, եթե URL-ները տարբեր են) և robots.txt։ Ստուգիր, որ անհատական հրավերների և «Իմ պատվերները» էջերը noindex են և sitemap-ում չկան։ Ստուգիր title և meta description բոլոր հիմնական էջերում։

4. 404 էջ։ Եթե չկա, ստեղծիր 404 էջ Siloona-ի ոճով (ivory ֆոն, Noto Serif Armenian, burgundy ակցենտ)՝ կարճ տեքստով 3 լեզվով և «Գլխավոր էջ» ու «Դիզայններ» կոճակներով։

Ստուգիր Lighthouse-ով mobile ռեժիմում առաջ և հետո, և գրիր թվերը։ Վերջում՝ ինչ է պետք ինձնից (Google Search Console-ում sitemap-ի ավելացում)։
```

## 5 · Կատալոգ (checklist 20, 24, ըստ ցանկության՝ 19, 21)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Մի փոխիր տեքստեր առանց իմ հաստատման։

1. Դիզայնների անուններ։ Կազմիր աղյուսակ՝ բոլոր դիզայնների կոդը (WEB-WED-02, wd-velvet և այլն), կատեգորիան և 2 առաջարկվող անուն հայերեն (մեկ բառ, ոճին համապատասխան. օր.՝ «Թավիշ», «Կակաչ»)։ ՍՊԱՍԻՐ իմ ընտրությանը։ Հաստատումից հետո ցուցադրիր անունը որպես գլխավոր, իսկ կոդը՝ փոքր տառերով կողքին, կատալոգում, դիզայնի էջում և checkout-ում՝ 3 լեզվով։

2. Լուսանկարների լիցենզիա։ Գտիր բոլոր դեմո լուսանկարները բոլոր դիզայններում։ Կազմիր աղյուսակ՝ ֆայլ, դիզայն, կա՞ աղբյուրը (CREDITS.md կամ մեկնաբանություն), լիցենզիան։ Նշիր այն նկարները, որոնց աղբյուրը անհայտ է։ Ոչինչ մի ջնջիր։

[Ըստ ցանկության՝ ջնջիր տողը, եթե պետք չէ]
```
