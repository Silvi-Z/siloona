# Siloona · Claude Code prompt-ներ հավելումների համար

Տուր Claude Code-ին **հերթով**, մեկ prompt՝ մեկ անգամ։ Յուրաքանչյուրից հետո ստուգիր արդյունքը, հետո անցիր հաջորդին։
**Prompt 0-ն պարտադիր է առաջինը**, որովհետև մնացածը կախված են դրանից։
«Ձեր սեղանը» ֆունկցիայի համար օգտագործիր առանձին ֆայլը՝ «siloona-seating-prompt.md», Prompt 0-ից հետո։

Ինչ կոդ չի պահանջում և այստեղ չկա. **Լրացուցիչ լեզու**, **Շտապ պատրաստում** և **Դիզայնի ադապտացիա տպագրի համար**. սրանք ծառայություններ են, որ դու ես անում։ Prompt 0-ը դրանք միայն ավելացնում է պատվերի ձևում որպես ընտրանք։

## Prompt 0 · Հիմք. հավելումների համակարգ և պատվերի ձև

```
Կարդա CLAUDE.md-ն և խստորեն հետևիր դրան։

## Նպատակը
Siloona-ն կավելացնի վճարովի հավելումներ թվային հրավերներին։ Այս առաջադրանքում ստեղծում ենք միայն ՀԻՄՔԸ. հավելումները պատվերի ձևում և հրավերի տվյալներում։ Ֆունկցիաները կավելացնենք հաջորդ prompt-ներով։

## Քայլ 1 · Ուսումնասիրություն
Ուսումնասիրիր և կարճ ներկայացրու.
- ինչպես են պահվում պատվերները և հրավերի տվյալները (schema.sql, payments.sql),
- ինչպես է աշխատում checkout-ը և ինչպես է հաշվվում գինը,
- որտեղ են գնային տարբերակների անունները և գները կոդում։
Հետո ներկայացրու ՊԼԱՆ և ՍՊԱՍԻՐ իմ հաստատմանը։

## Քայլ 2 · Հավելումների կարգավորում
Ստեղծիր մեկ կարգավորման ֆայլ (օր.՝ src/config/addons.js), որտեղ յուրաքանչյուր հավելում ունի. id, անուն 3 լեզվով (hy/ru/en), կարճ նկարագրություն 3 լեզվով, գին ֏, տեսակ ("feature"՝ փոխում է հրավերը, "service"՝ ծառայություն է, կոդը չի փոխում), enabled (true/false)։

Հավելումները և ԺԱՄԱՆԱԿԱՎՈՐ գները (ես դեռ վերջնական չեմ հաստատել, թող հեշտ լինի փոխել մեկ տեղում).
- calendar · Ավելացնել օրացույցում · 0 · feature (ներառված է բոլոր հրավերներում, պատվերի ձևում որպես ընտրանք ՉԻ ցուցադրվում)
- personal_greeting · Անհատական դիմում հյուրին · 3000 · feature
- seating · Ձեր սեղանը · 4000 · feature
- live_schedule · Կենդանի ծրագիր + տաքսի · 3000 · feature
- extra_rsvp_question · Լրացուցիչ հարց RSVP-ում · 1000 · feature
- wishes · Մաղթանքների գիրք · 3000 · feature
- thank_you_page · Շնորհակալական էջ · 2000 · feature
- extra_language · Լրացուցիչ լեզու · 2000 · service
- rush · Շտապ պատրաստում (24 ժամ) · 3000 · service (միայն «Հարմարեցված դիզայն»-ի համար)
- print_adaptation · Դիզայնի ադապտացիա տպագրի համար · 5000 · service

Սկզբում enabled: true միայն calendar-ի և service տեսակի հավելումների համար։ Մյուսները կմիացնեմ, երբ ֆունկցիան պատրաստ լինի։

## Քայլ 3 · Տվյալներ
- Նոր migration ֆայլ (մի փոխիր առկա SQL ֆայլերը). պատվերում պահել ընտրված հավելումների ցանկը և դրանց գինը պատվերի պահին, իսկ հրավերում՝ միացված ֆունկցիաների ցանկը (օր.՝ features jsonb)։
- Հրավերը ֆունկցիան ցույց է տալիս ՄԻԱՅՆ եթե այն միացված է տվյալ հրավերի համար։
- Գինը պետք է հաշվվի server-ում կարգավորման ֆայլից, ոչ թե վստահվի browser-ից եկած թվին։

## Քայլ 4 · Պատվերի ձև
- Checkout-ում, գնային տարբերակից հետո, ավելացրու «Հավելումներ» բաժին. checkbox-ներ անունով, մեկ տողանոց նկարագրությամբ և գնով։ Ընդհանուր գինը թարմանում է անմիջապես։
- Ցույց տուր միայն enabled հավելումները և միայն այն տարբերակների համար, որոնց համար դրանք կիրառելի են։
- Դիզայնը՝ առկա checkout-ի ոճով, առանց նոր ոճերի կամ տառատեսակների։ Mobile-ում հարմար սեղմվող տարածքներ։
- Telegram ծանուցման և պատվերի email-ի մեջ ավելացրու ընտրված հավելումների ցանկը։
- 3 լեզու։

## Քայլ 5 · Ստուգում
- Պատվեր առանց հավելումների՝ աշխատում է ինչպես առաջ։
- Պատվեր 2–3 հավելումով՝ գինը ճիշտ է և՛ էկրանին, և՛ server-ում, և՛ վճարման մեջ։
- Browser-ից կեղծ գին ուղարկելու փորձը չի աշխատում։
- Բոլոր առկա թեստերը անցնում են։ Ավելացրու թեստ գնի հաշվարկի համար։
- Ստուգիր 375px mobile-ում։

Վերջում գրիր. ինչ է փոխվել, որ ֆայլերում, ինչ migration պետք է գործարկեմ production-ում, ինչ ես ստուգել։
```

## Prompt 1 · Ավելացնել օրացույցում (անվճար, բոլոր հրավերներում)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Prompt 0-ի հավելումների համակարգն արդեն կա։

Ավելացրու բոլոր հրավերներում «Ավելացնել օրացույցում» կոճակ (calendar)։
- Սեղմելիս առաջարկում է երկու տարբերակ. Google Calendar (հղում՝ նախապես լրացված տվյալներով) և Apple / այլ օրացույց (.ics ֆայլ)։
- Միջոցառման տվյալները. անվանում (օր.՝ «Աննա և Միքայելի հարսանիք»), սկիզբ և ավարտ Asia/Yerevan ժամային գոտով, հիմնական վայրի հասցե, հրավերի հղումը նկարագրության մեջ, հիշեցում 1 օր առաջ։
- Եթե ավարտի ժամ չկա, դիր սկիզբ + 5 ժամ։
- .ics ֆայլը պետք է ճիշտ աշխատի iPhone Safari-ում և Android Chrome-ում, ինչպես նաև Instagram/Telegram-ի ներքին բրաուզերում։ Եթե ներքին բրաուզերը ֆայլը չի բացում, ցույց տուր հուշում «Բացեք հրավերը բրաուզերում»։
- Կոճակի տեղը և տեսքը յուրաքանչյուր դիզայնում պետք է համապատասխանի տվյալ դիզայնի ոճին (սովորաբար ամսաթվի կամ հետհաշվարկի մոտ)։ Մի պարտադրիր նույն տեսքը բոլորին։
- Սկզբում արա ՄԵԿ դիզայնում, ցույց տուր ինձ, հետո մյուսներում։
- 3 լեզու։

Ստուգիր Google Calendar-ի հղումը և .ics ֆայլը իրական հեռախոսում, եթե կարող ես, կամ բացատրիր, թե ինչպես ստուգեմ ես։
```

## Prompt 2 · Անհատական դիմում հյուրին (personal_greeting)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Prompt 0-ի հավելումների համակարգն արդեն կա։

Նպատակը. երբ հյուրը բացում է իր անհատական հղումը, հրավերը դիմում է նրան անունով. «Սիրելի Արամ և Անի, սպասում ենք ձեզ»։

1. Ուսումնասիրիր guest-links-ի առկա իրականացումը և ներկայացրու, թե ինչպես ես պլանավորում։ Սպասիր իմ հաստատմանը։
2. Յուրաքանչյուր անհատական հղում պետք է ունենա դիմելու անուն (display_name)։ Եթե չկա, ավելացրու migration-ով։
3. Դիմումը ցույց տուր հրավերի սկզբում, տվյալ դիզայնի տառատեսակով և ոճով։ Ընդհանուր հղումով բացելիս հրավերը մնում է ինչպես հիմա։
4. Ներմուծման script (օր.՝ scripts/import-guests.js). CSV ֆայլ (display_name, ըստ ցանկության՝ phone կամ նշում) → ստեղծում է անհատական հղումներ և վերադարձնում CSV՝ անուն + հղում, որպեսզի զույգը ուղարկի դրանք հյուրերին։ Կրկնակի գործարկելիս չի կրկնօրինակում։
5. Անհատական հղումները պետք է լինեն երկար և չգուշակվող, և դրանք չպետք է բացահայտեն այլ հյուրերի անունները։
6. Եթե հյուրն այս հղումով լրացնում է RSVP-ն, նրա անունը թող նախապես լրացված լինի։
7. Ֆունկցիան աշխատում է միայն այն հրավերներում, որտեղ personal_greeting-ը միացված է։
8. Սկզբում ՄԵԿ դիզայնում։ 3 լեզու։

Ստուգիր. ընդհանուր հղում, անհատական հղում, գոյություն չունեցող հղում (պետք է բացվի սովորական հրավերը, առանց սխալի), 375px mobile։
```

## Prompt 3 · Կենդանի ծրագիր + տաքսի (live_schedule)

```
Կարդա CLAUDE.md-ն և հետևիր դրան։ Prompt 0-ի հավելումների համակարգն արդեն կա։

Նպատակը. հայկական հարսանիքն անցնում է մի քանի վայրում (հարսի տուն, փեսայի տուն, եկեղեցի, ռեստորան)։ Հարսանիքի օրը հրավերի «Ծրագիր» բաժինը դառնում է կենդանի.
- ընդգծվում է այն փուլը, որը հիմա է ընթանում («Հիմա»),
- անցած փուլերը դառնում են ավելի բաց,
- հաջորդ փուլի մոտ հայտնվում են կոճակներ. «Ճանապարհ» (քարտեզ) և «Տաքսի»։

1. Ուսումնասիրիր, թե ինչպես են հիմա պահվում ծրագիրը և վայրերը հրավերներում։ Ներկայացրու պլանը և սպասիր հաստատմանը։
2. Յուրաքանչյուր փուլ պետք է ունենա սկզբի ժամ, ըստ ցանկության՝ ավարտի ժամ, վայր, հասցե և կոորդինատներ։ Եթե ավարտ չկա, փուլը ավարտվում է հաջորդի սկզբում։
3. Ժամանակը միշտ Asia/Yerevan, անկախ հյուրի հեռախոսի ժամային գոտուց։
4. Կենդանի վիճակը միանում է միայն միջոցառման օրը։ Մինչ այդ և դրանից հետո ծրագիրը ցույց է տրվում սովորական ձևով։
```
