# Claude Code prompt · «Ձեր սեղանը» ֆունկցիան հրավերում

Տուր VS Code-ում ամբողջությամբ։ Claude Code-ը նախ կներկայացնի պլանը. ստուգիր այն և հաստատիր, հետո միայն կսկսի կոդը։

```
Կարդա CLAUDE.md-ն և խստորեն հետևիր դրան։

## Նպատակը

Ավելացնել հրավերներում նոր, ըստ ցանկության միացվող բաժին՝ «Ձեր սեղանը»։ Հյուրը հրավերից կարող է իմանալ իր սեղանի համարը.

1. Մինչև բացման պահը բաժինը ցույց է տալիս տեքստ. «[Ամսաթիվ]-ին այստեղ կտեսնեք ձեր սեղանը»։
2. Բացման պահից հետո (զույգի ընտրած ամսաթիվ և ժամ, Asia/Yerevan) հայտնվում է «Իմացեք ձեր սեղանը» կոճակը։
3. Կոճակը բացում է մոդալ պատուհան. հյուրը գրում է իր անունը և տեսնում իր սեղանը (օր.՝ «Սեղան 7»)։
4. Եթե հյուրը բացել է իր անհատական հղումը (guest-links), սեղանը ցույց է տրվում ավտոմատ, առանց անուն գրելու։

Ֆունկցիան միացված է միայն այն հրավերներում, որտեղ զույգը դա պատվիրել է։ Մնացած հրավերներում ոչինչ չպետք է փոխվի։

## Քայլ 1 · Ուսումնասիրություն (նախքան որևէ փոփոխություն)

Ուսումնասիրիր և ինձ կարճ ներկայացրու.
- ինչպես են կառուցված հրավերները (առանձին HTML դեմոներ, React կոմպոնենտներ, թե երկուսը),
- ինչպես են պահվում հրավերի տվյալները Supabase-ում (schema.sql),
- ինչպես են աշխատում guest-links-ը (guest-links.sql) և RSVP-ն,
- որ API/serverless ֆունկցիաներն են արդեն կան, և ինչպես է աշխատում RATE_LIMITS-ը։

Հետո ներկայացրու ՊԼԱՆ. տվյալների մոդել, API, UI, ինչպես է լրացվում սեղանների ցուցակը, ինչ ֆայլեր կփոխվեն։ ՍՊԱՍԻՐ իմ հաստատմանը, նոր միայն սկսիր։

## Քայլ 2 · Տվյալներ (Supabase)

Առաջարկվող կառուցվածք (հարմարեցրու առկա schema-ին).
- Միջոցառման կարգավորումներում. seating_enabled (boolean), seating_reveal_at (timestamptz)։
- Նոր աղյուսակ seating. id, event/invitation id, guest_name (ինչպես զույգն է գրել), normalized_name (որոնման համար), table_label (տեքստ՝ «7», «VIP», «Ընտանիք»), guest_link_id (nullable՝ կապ անհատական հղման հետ), created_at։
- Նոր migration ֆայլ, ոչ թե առկա SQL ֆայլերի փոփոխություն։ Այն պետք է անվտանգ գործարկվի production-ում։

Անվտանգություն.
- RLS. seating աղյուսակը հանրության համար ԸՆԴՀԱՆՐԱՊԵՍ չի կարդացվում։
- Հյուրը երբեք չպետք է տեսնի ամբողջ ցուցակը կամ ուրիշների սեղանները։
- Որոնումը միայն server-side ֆունկցիայով, որը վերադարձնում է մեկ արդյունք կամ «չի գտնվել»։
- Մինչև seating_reveal_at-ը server-ը չի վերադարձնում ոչ մի սեղան, նույնիսկ եթե հարցումն ուղարկվի ուղղակի։
- Rate limit որոնման համար (առկա RATE_LIMITS մեխանիզմով)։

## Քայլ 3 · Անունով որոնում

Անունները գրվում են տարբեր ձևերով, ուստի որոնումը պետք է ներողամիտ լինի.
- տառաչափ, բացատներ, գծիկներ, կետադրություն՝ անտեսել,
- «և», «&», «and» տարբերակները՝ միևնույնը,
- հայերեն ↔ լատինատառ տրանսլիտերացիա (Անի ↔ Ani, Արամ ↔ Aram)։ Օգտագործիր պարզ քարտեզ, առանց նոր dependency-ի, եթե հնարավոր է,
- եթե հյուրը գրել է միայն անունը, և այն եզակի է՝ վերադարձնել արդյունքը,
- եթե համընկնում է մի քանի մարդ (օր.՝ երկու «Անի»)՝ խնդրել գրել նաև ազգանունը, ՉԱՑՈՒՑԱԴՐԵԼՈՎ մյուսների տվյալները,
- եթե չի գտնվում՝ «Ձեր անունը չգտանք։ Խնդրում ենք մոտենալ մուտքի մոտ գտնվող ցուցակին կամ դիմել կազմակերպիչներին»։

Գրիր unit թեստեր normalization-ի և որոնման համար (առնվազն 15 դեպք, այդ թվում՝ հայերեն/լատինատառ, կրկնվող անուններ, դատարկ մուտք)։

## Քայլ 4 · Սեղանների ցուցակի լրացում

Առայժմ առանց նոր admin էջի։ Ստեղծիր script (օր.՝ scripts/import-seating.js), որը.
- կարդում է CSV ֆայլ (սյունակներ. guest_name, table_label, ըստ ցանկության՝ guest_link_id),
- ներմուծում է այն տվյալ միջոցառման համար,
- կրկնակի գործարկելիս թարմացնում է ցուցակը, ոչ թե կրկնօրինակում,
- վերջում ցույց է տալիս. քանի տող է ներմուծվել, որոնք են բաց թողնվել և ինչու։

Ավելացրու CSV-ի օրինակ ֆայլ՝ թեստային տվյալներով, և կարճ ձեռնարկ README-ում կամ DEPLOY.md-ում։

## Քայլ 5 · UI

- Ֆունկցիայի տրամաբանությունը մեկն է բոլոր հրավերների համար, բայց ՏԵՍՔԸ պետք է համապատասխանի յուրաքանչյուր հրավերի դիզայնին (տառատեսակներ, գույներ, անիմացիաներ)։ Մի պարտադրիր նույն տեսքը բոլոր դիզայններին։
- Սկզբում իրականացրու ՄԵԿ հրավերում (wd-velvet կամ այն, որ առաջարկես), ես կստուգեմ, հետո կավելացնենք մյուսներում։
- Մոդալը. մեծ, հարմար input հեռախոսի համար, autocomplete="off", Enter-ով ուղարկում, բեռնման վիճակ, պարզ արդյունք (սեղանի համարը մեծ տառերով), փակելու կոճակ։ Մատչելիություն. ֆոկուս մոդալի ներսում, Escape-ով փակում, aria-ներ։
- Տեքստերը 3 լեզվով (hy/ru/en)՝ առկա i18n համակարգով։
- Անհատական հղումով եկած հյուրի դեպքում բաժինը միանգամից ցույց է տալիս «Ձեր սեղանը՝ 7», առանց մոդալի։
- Մինչև բացումը՝ միայն տեքստ ամսաթվով, առանց կոճակի։

## Քայլ 6 · Ստուգում

- Unit թեստեր (Քայլ 3) և առկա բոլոր թեստերը պետք է անցնեն։
- Ստուգիր 4 վիճակները. ֆունկցիան անջատված, մինչև բացումը, բացումից հետո՝ անունով, բացումից հետո՝ անհատական հղումով։
- Ստուգիր, որ մինչև բացումը API-ն ոչինչ չի վերադարձնում։
- Ստուգիր 375px mobile-ում և desktop-ում, ինչպես նաև Instagram/Telegram-ի ներքին բրաուզերում, եթե հնարավոր է։
- Ստուգիր, որ մյուս հրավերներում ոչինչ չի փոխվել։
- Console-ում սխալներ չպետք է լինեն։
```
